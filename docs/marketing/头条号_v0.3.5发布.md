## 一、符号级精准引用系统（# / @）

### 功能说明

v0.3.5 引入完整的代码符号引用体系，支持通过 `#` 和 `@` 符号在对话中快速引用代码实体。

| 符号 | 引用类型 | 使用示例 | 作用范围 |
|------|---------|---------|---------|
| `#` | 函数/类/符号 | `#verifyEmail` | 当前打开文件的符号列表 |
| `@` | 文件路径 | `@auth.ts` 或 `@auth` | 项目全局文件模糊匹配 |

### 技术实现

- **后端**：独立 `symbol_scanner` 模块，基于正则表达式扫描函数、类、结构体定义
- **前端**：实时模糊搜索面板，支持键盘导航（↑↓ 选择，Enter 确认，Esc 关闭）
- **精度**：引用精确到行号，上下文自动提取 ±15 行代码

### 适用场景

- 定位大型文件中的特定函数
- 跨文件询问实现细节
- 批量选中多个符号进行重构讨论

## 二、Vibe 模式 2.0：真正的零打扰体验

### 什么是 Vibe 模式

Vibe 模式是 IfAI 独创的"感性工作流"——AI 作为背景智能辅助，只读操作完全静默执行，不弹窗、不打断。

### v0.3.5 改进点

**修复范围**：
- 工具名归一化引擎（支持 `List Directory`、`list_dir`、`agent_list_dir` 等变体）
- 100% 覆盖只读类工具（Read File、Search、Glob、Scan Directory 等）
- 即时执行通道（Fast-Track），工具接收完毕立即执行

**性能数据**：
- 工具执行反馈延迟：15ms（行业平均 200ms+）
- 弹窗干扰次数：0（v0.3.4 为平均每会话 3-5 次）

### 与 Spec 模式的区别

| 模式 | 工具执行 | 适用场景 |
|------|---------|---------|
| **Vibe** | 只读工具静默执行，写入工具物理隔离 | 代码理解、架构梳理、学习研究 |
| **Spec** | 所有工具按需授权，细粒度控制 | 代码重构、文件修改、生产环境 |

## 三、工业级并发控制系统

### 问题背景

大规模 RAG（检索增强生成）场景下，DeepSeek、OpenAI 等云端 API 频繁返回 **429 Rate Limit** 错误，导致任务中断。

### 解决方案

引入中央并发管理器（基于 Semaphore 信号量）：

- **全局限流**：最大 5 个并发工具执行
- **智能排队**：超出限制的请求自动进入 FIFO 队列
- **生命周期保护**：从工具检查、执行到文件树刷新，全链路受控

### 实测结果

| 测试项 | v0.3.4 | v0.3.5 | 提升 |
|--------|--------|--------|------|
| 连续读取 100+ 文件 | 7 次 429 错误 | 0 次 | **100% 解决** |
| UI 响应延迟 | 220ms | 15ms | **14.6x 提升** |
| 任务完成率 | 86% | 100% | **+14%** |

## 六、技术架构亮点

### 符号扫描引擎

```rust
// Rust 后端实现，毫秒级扫描
#[tauri::command]
async fn get_file_symbols(path: String) -> Vec<SymbolInfo> {
    let content = fs::read_to_string(&path).await?;
    let scanner = SymbolScanner::new(&content);
    scanner.find_functions().find_classes().collect()
}
```

### 并发控制核心

```typescript
// TypeScript 前端实现，全局单例
class ConcurrencyLimiter {
  private semaphore = new Semaphore(5);

  async execute<T>(fn: () => Promise<T>): Promise<T> {
    await this.semaphore.acquire();
    try {
      return await fn();
    } finally {
      this.semaphore.release();
    }
  }
}
```
